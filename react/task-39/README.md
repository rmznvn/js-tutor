# React: динамический список участников
Выпуск: 13 ноября 2026.

## Условие
На странице записи на встречу добавляются участники. Старт: одна пустая строка с ID1. Минимум одна строка, максимум три.
Для каждого участника controlled input имени и кнопка удаления. «Добавить участника» добавляет пустую строку с новым стабильным ID. Достигнут максимум — добавление недоступно; осталась одна строка — удаление недоступно.
Удаление средней строки не должно переносить имена между участниками. Покажи количество строк и заполненных имён, игнорируя пробелы.
Критерии: массив участников обновляется неизменяемо; key — постоянный ID, а не индекс; следующий ID монотонно растёт и не переиспользуется. Проверка и отправка на сервер не требуются.
Данные состояния: { guests:[{id:1,name:""}], nextId:2 }.
Крайние случаи: три строки → удалить среднюю → добавить новую; пробельное имя; попытка удалить последнюю или добавить четвёртую.
Время: 30–40 минут.

## Как рассуждать — вопросы интервьюера
1. Почему индекс массива не подходит как key для редактируемых строк?
2. Когда создавать ID, чтобы он не менялся при рендере?
3. Какие данные хранить, а какие вычислять?

## Примеры ответов вслух
«У участника должен быть постоянный ID. При удалении индекс следующих строк сдвигается. key по ID сохраняет связь строки с её данными и экземпляром компонента».
«Следующий ID храню вместе со списком. При добавлении использую его и увеличиваю. Рендер только читает данные; случайные ключи внутри map не создаю».
«Изменение имени сделаю через map, удаление через filter, добавление через spread. Лимиты проверю и в обработчиках, а число заполненных строк вычислю через trim/filter».
«Проверю имена после удаления середины, границы количества и то, что новый ID не совпадает с ранее удалённым».

## Пошаговый разбор
1. Создай объект состояния со списком и nextId.
2. Добавляй строку функциональным обновлением, увеличивая nextId.
3. Редактируй нужный объект через map.
4. Удаляй через filter, сохраняя минимум одну строку.
5. Используй ID для key и связи label/input.
6. Вычисляй заполненное количество из текущих строк.

Типичные ошибки: key=index; генерация ключа при каждом рендере; мутация guest.name; повторное использование длины массива как ID; удаление последней строки; отдельное состояние счётчика.
Ручные проверки: добавить 2 строки → всего 3; заполнить Анна/Борис/Вера; удалить ID2 → Анна/Вера остаются у ID1/3; добавить → новая пустая ID4; пробелы не увеличивают заполненное количество; одна строка не удаляется.
Альтернатива: создать ID через crypto.randomUUID в обработчике добавления. Это удобно для независимых списков и объединения данных, но добавляет новый API; ID нельзя создавать внутри функционального updater с побочными эффектами. Для одного учебного списка числовой счётчик состояния проще.

### src/App.jsx

```jsx
import { useState } from "react";

const MAX_GUESTS = 3;

export default function GuestList() {
  // Следующий ID хранится вместе со списком, без случайных ключей в render.
  const [state, setState] = useState({
    guests: [{ id: 1, name: "" }],
    nextId: 2,
  });

  function addGuest() {
    setState((current) => {
      // Проверяем лимит также в обработчике.
      if (current.guests.length >= MAX_GUESTS) return current;
      return {
        guests: [...current.guests, { id: current.nextId, name: "" }],
        nextId: current.nextId + 1,
      };
    });
  }

  function updateGuest(id, name) {
    setState((current) => ({
      ...current,
      guests: current.guests.map((guest) =>
        guest.id === id ? { ...guest, name } : guest
      ),
    }));
  }

  function removeGuest(id) {
    setState((current) => {
      // Оставляем хотя бы одну строку.
      if (current.guests.length === 1) return current;
      return {
        ...current,
        guests: current.guests.filter((guest) => guest.id !== id),
      };
    });
  }

  // Пробельное имя не считается заполненным.
  const filledCount = state.guests.filter(
    (guest) => guest.name.trim() !== ""
  ).length;

  return (
    <main>
      <h1>Участники встречи</h1>
      <p>Можно добавить от одного до трёх участников.</p>
      <ul>
        {state.guests.map((guest) => (
          // Стабильный ID сохраняет соответствие поля и участника при удалении.
          <li key={guest.id}>
            <label htmlFor={"guest-" + guest.id}>
              Имя участника {guest.id}
            </label>
            <input
              id={"guest-" + guest.id}
              value={guest.name}
              onChange={(event) => updateGuest(guest.id, event.target.value)}
            />
            <button
              type="button"
              aria-label={"Удалить участника " + guest.id}
              disabled={state.guests.length === 1}
              onClick={() => removeGuest(guest.id)}
            >
              Удалить
            </button>
          </li>
        ))}
      </ul>
      <button
        type="button"
        disabled={state.guests.length >= MAX_GUESTS}
        onClick={addGuest}
      >
        Добавить участника
      </button>
      <p role="status">
        Строк: {state.guests.length}. Заполнено: {filledCount}.
      </p>
    </main>
  );
}
```
