# React: профиль с сохранением и отменой

Выпуск за понедельник 16 ноября 2026. Добавлен 17 ноября как пропущенный выпуск. Уровень: Junior+.

## Условие
Пользователь редактирует профиль, а опубликованная подпись меняется только после «Сохранить». Вход: {name:"Наталья",role:"Webflow developer"}. Имя обязательно после trim, роль необязательна. Храни сохранённый профиль и черновик отдельно. Показывай несохранённые изменения, отключай сохранение без изменений или с пустым именем. «Отменить» восстанавливает последнее сохранение. Сохранение только в памяти, без сервера и localStorage. Критерии: исходный профиль не мутируется; dirty вычисляется сравнением полей; отправка Enter работает. Время: 30–40 минут. Крайние случаи: имя из пробелов; изменение и возврат исходного текста; отмена после второго сохранения.

## Как рассуждать — вопросы интервьюера
1. Зачем два объекта состояния, если обычно нельзя дублировать данные?
2. Почему нельзя сравнить draft === saved?
3. Нужно ли хранить dirty через useState или вычислять в useEffect?

## Примеры ответов вслух
«Здесь два объекта отражают разные версии: подтверждённую и ещё не сохранённую. Такое разделение задано поведением продукта. Во время ввода меняется только draft»

«Два объекта с одинаковыми полями могут иметь разные ссылки. Сравню name и role. Проверю, что возврат прежнего текста снова делает форму неизменённой»

«dirty полностью определяется двумя объектами, поэтому вычислю его при рендере. Это исключает рассинхронизацию и не требует useEffect. В submit повторю проверку, а после trim обновлю и saved, и draft»

## Пошаговый разбор
1. Создай saved и draft; отдельное сообщение сообщает результат операции.
2. Свяжи поля с draft через value/onChange, обновляй объект через spread.
3. Вычисли dirty и ошибку имени непосредственно при рендере.
4. На submit вызови preventDefault, проверь условия, нормализуй строки и сохрани новую версию.
5. На отмену скопируй последнее saved в draft. Не возвращай initialProfile после каждого сохранения.

Типичные ошибки: Мутировать draft.name; менять saved при каждом вводе; сравнивать ссылки; хранить dirty отдельно; отменять к начальному профилю; сообщать об отправке на сервер, которого нет.

Ручные проверки: Измени роль: подпись saved прежняя, dirty=true. Отмени: поля восстановлены. Сохрани новое имя с пробелами: пробелы убраны, dirty=false. Очисти имя: сохранить нельзя. Сохрани дважды разные данные и проверь отмену к последней версии. Роль можно оставить пустой.

Альтернатива: Для большого фиксированного профиля можно вынести редактор в дочерний компонент и сбрасывать его через key при смене сохранённой версии. Это удобно при переключении сущностей, но сбрасывает всё локальное состояние и может терять фокус. Для двух полей явный draft проще.

### src/App.jsx

```jsx
import { useState } from "react";

const initialProfile = { name: "Наталья", role: "Webflow developer" };

export default function ProfileEditor() {
  // Сохранённые данные и редактируемый черновик имеют разный смысл.
  const [saved, setSaved] = useState(initialProfile);
  const [draft, setDraft] = useState({ ...initialProfile });
  const [message, setMessage] = useState("");
  // Сравниваем содержимое полей, а не ссылки объектов: это производное значение.
  const dirty = draft.name !== saved.name || draft.role !== saved.role;
  // trim нужен для проверки имени из одних пробелов.
  const error = draft.name.trim() ? "" : "Введите имя";

  function update(field, value) {
    // Копия сохраняет другое поле. Функциональное обновление берёт актуальный draft.
    setDraft((current) => ({ ...current, [field]: value }));
    setMessage("");
  }
  function save(event) {
    event.preventDefault(); // Обрабатываем submit без перезагрузки страницы.
    if (error || !dirty) return; // Повторяем проверку внутри обработчика.
    const next = { name: draft.name.trim(), role: draft.role.trim() };
    setSaved(next); // Фиксируем подтверждённые значения.
    setDraft({ ...next }); // Убираем отличия, вызванные нормализацией пробелов.
    setMessage("Сохранено в памяти страницы"); // Здесь нет запроса к серверу.
  }
  function cancel() {
    setDraft({ ...saved }); // Возвращаем именно последнее сохранение, не initialProfile.
    setMessage("Изменения отменены");
  }
  return (
    <main>
      <h1>Редактор профиля</h1>
      <p>Сохранено: {saved.name} — {saved.role || "Роль не указана"}</p>
      <form onSubmit={save} noValidate>
        <label htmlFor="name">Имя</label>
        {/* Управляемое поле отображает draft; saved меняется только по submit. */}
        <input id="name" value={draft.name} onChange={(e) => update("name", e.target.value)} aria-invalid={Boolean(error)} aria-describedby="name-error" />
        <p id="name-error">{error}</p>
        <label htmlFor="role">Роль (необязательно)</label>
        <input id="role" value={draft.role} onChange={(e) => update("role", e.target.value)} />
        <p>{dirty ? "Есть несохранённые изменения" : "Все изменения сохранены"}</p>
        {/* disabled — удобство интерфейса; проверка в save остаётся обязательной. */}
        <button type="submit" disabled={!dirty || Boolean(error)}>Сохранить</button>
        <button type="button" disabled={!dirty} onClick={cancel}>Отменить</button>
      </form>
      <p role="status">{message}</p>
    </main>
  );
}
```
