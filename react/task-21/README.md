# Отмена последнего удаления — React

Выпуск **2026-10-23**. Время: 30–40 минут.

## Условие

Редактор удаляет статьи и может отменить одно последнее удаление, восстановив исходную позицию статьи.

### Входные данные и критерии готовности

- Статьи: Обзор продукта, Новости команды, Инструкция по настройке.
- Кнопка удаления меняет только выбранную строку; перед действием сохраняется снимок массива.
- Кнопка отмены восстанавливает список до последнего удаления и затем блокируется.
- Второе удаление заменяет снимок первого: история глубиной один, без таймеров и API.
- Список и previousItems хранятся в одном объекте state и обновляются функционально.
- Пустое состояние «Статей нет»; возможность отмены сохраняется.

### Крайние случаи

- Удалить среднюю и отменить → исходный порядок.
- Удалить B, затем C, отменить → A и C.
- Удалить последнюю; повторное нажатие отмены недоступно.

## Как рассуждать

- Что нужно сохранить для отмены?
- Можно ли сохранить старый массив по ссылке?
- Почему объединить список и снимок?

Начни с источника данных и результата одного действия. Отдели состояние от вычисляемых значений. Предскажи результат на маленьком примере до выбора метода.

## Примеры ответов вслух

> «Сохраню весь список до удаления. Тогда вернутся и данные, и исходный порядок, без отдельной логики вставки по индексу.»

> «Да, если я неизменяемо обновляю данные. filter создаёт новый массив, старый остаётся безопасным снимком. Глубокая копия здесь не нужна.»

> «Они меняются в одном действии, поэтому один функциональный updater вернёт согласованную пару. После отмены previousItems станет null; проверю двойное удаление и восстановление.»

## Пошаговый разбор

1. Создать state {items, previousItems:null}.
2. При удалении проверить существование ID.
3. Вернуть новый список через filter и старый список как снимок.
4. При отмене восстановить снимок и сбросить его в null.
5. Вычислить счётчик, доступность отмены и пустоту из state.

## Типичные ошибки

- push/splice портят снимок.
- Сохранение массива после удаления восстанавливает уже сокращённый список.
- Отдельные несогласованные setters для списка и его истории.
- truthy-проверка вместо явного null не объясняет контракт снимка.

## Альтернативный способ

Хранить только удалённый объект и его индекс. Это экономнее для большого списка, но восстановление позиции усложняется при других изменениях. Снимок проще для маленького списка с одной отменой.

## Ручная проверка

Удали вторую и отмени; удали вторую, затем третью и отмени — вернётся только третья. Удали все и отмени последнее. Проверь disabled после отмены.

## Запуск

Из папки задачи: `npm ci`, затем `npm run dev`. Для Codespaces: `npm run dev -- --host 0.0.0.0`, затем Open in Browser. Сборка: `npm run build`.

### src/components/UndoableList.jsx

```jsx
import { useState } from "react";

const initialArticles = [
  { id: 1, title: "Обзор продукта" },
  { id: 2, title: "Новости команды" },
  { id: 3, title: "Инструкция по настройке" },
];

export default function UndoableList() {
  // Список и снимок меняются вместе: объединяем их в один state.
  // null означает, что отменять нечего; [] может быть настоящим снимком.
  const [state, setState] = useState({
    items: initialArticles,
    previousItems: null,
  });

  function removeArticle(id) {
    setState((current) => {
      // Повторное удаление отсутствующего ID не перезаписывает снимок.
      if (!current.items.some((item) => item.id === id)) return current;
      return {
        // filter возвращает новый массив, не меняя предыдущий.
        items: current.items.filter((item) => item.id !== id),
        // Старый массив безопасно сохранить по ссылке:
        // мы не мутируем его и не изменяем объекты статей.
        previousItems: current.items,
      };
    });
  }

  function undo() {
    setState((current) => {
      if (current.previousItems === null) return current;
      // Восстанавливаем весь порядок и отключаем повторную отмену.
      return { items: current.previousItems, previousItems: null };
    });
  }

  return (
    <main>
      <h1>Статьи</h1>
      <p>Осталось: {state.items.length}</p>
      <button type="button" disabled={state.previousItems === null} onClick={undo}>
        Отменить последнее удаление
      </button>
      {state.items.length === 0 ? <p>Статей нет</p> : (
        <ul>
          {state.items.map((article) => (
            <li key={article.id}>
              {article.title}
              <button type="button" onClick={() => removeArticle(article.id)}>
                Удалить
              </button>
            </li>
          ))}
        </ul>
      )}
    </main>
  );
}

```
