# JavaScript → React: показ и скрытие пароля
Выпуск: 4 ноября 2026.

## Условие
В интерфейсе есть поле пароля и кнопка «Показать пароль». Поле изначально пустое, type=password.
Нажатие переключает type между password/text и подпись между «Показать пароль»/«Скрыть пароль». Введённый текст сохраняется, в том числе после редактирования в открытом режиме.
Сделай DOM- и React-версии. Поле не заменяй другим элементом. Пароль не выводи в консоль, текст страницы или хранилище.
Готово: один input, кнопка type=button доступна через Tab и Enter/Space; label связан с полем; aria-controls указывает на input. Это отдельный контрол без отправки формы.
Крайние случаи: пустое поле; несколько переключений после ввода; изменить текст в видимом режиме и скрыть.
Время: 15–20 минут на обе версии.

## Как рассуждать
1. Нужно ли создавать два input для разных режимов?
2. Какие данные различаются в DOM- и React-версиях?
3. Какой смысл сообщает подпись кнопки?

## Примеры ответов вслух
«Сохраню один input, меняя только type. Тогда не придётся переносить значение между двумя полями. В React не добавлю сменяющийся key, чтобы не создавать новый элемент».
«В DOM текст хранится в самом input, а boolean управляет видимостью. В controlled React поле получает value из password, плюс отдельный boolean isVisible».
«Подпись сообщает следующее действие. Поэтому при открытом тексте напишу “Скрыть пароль”. Дополнительный aria-pressed для такой кнопки не нужен».
«Проверю сохранность точной строки после нескольких переключений и после редактирования. Проверю кнопку клавиатурой; пароль нигде отдельно не печатаю».

## Пошаговый разбор
1. Создай input с type=password и связанный label.
2. Заведи isVisible=false.
3. На клик инвертируй флаг.
4. Вычисли type и подпись из флага.
5. В DOM обнови свойства существующих элементов; в React передай props того же input.
6. Проверь клавиатуру и сохранность значения.

Ошибки: пересоздавать input через innerHTML; менять key при переключении; сбрасывать password вместе с видимостью; забывать type=button внутри будущей формы.
Проверки: ввод Example!42 → показать → тот же текст; изменить на Example!43 → скрыть/показать → Example!43; пустое поле не заполняется само; Enter/Space на кнопке переключают режим.
Альтернатива: checkbox «Показывать пароль». checked прямо отражает режим и может быть понятнее как постоянная настройка. Кнопка компактнее и сообщает следующее действие; два варианта подходят разным макетам.

### src/App.jsx

```jsx
import { useState } from "react";

export default function PasswordVisibility() {
  const [password, setPassword] = useState("");
  const [isVisible, setIsVisible] = useState(false);

  return (
    <main>
      <h1>Проверка введённого пароля</h1>
      <label htmlFor="password">Пароль</label>
      <input
        id="password"
        // Меняется prop одного input; другой key ему не задаём.
        // Переключение видимости не сбрасывает введённое значение.
        type={isVisible ? "text" : "password"}
        autoComplete="current-password"
        value={password}
        onChange={(event) => setPassword(event.target.value)}
      />
      <button
        type="button"
        aria-controls="password"
        // Функционально инвертируем актуальный флаг.
        onClick={() => setIsVisible((current) => !current)}
      >
        {/* Подпись сообщает следующее действие; aria-pressed не добавляем. */}
        {isVisible ? "Скрыть пароль" : "Показать пароль"}
      </button>
      {/* Значение password используется только как value поля. */}
    </main>
  );
}
```
