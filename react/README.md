## 1. К какой категории относится избранное

**Категория: управление выбором нескольких элементов.**

У нас есть список статей. Пользователь может независимо выбрать несколько статей, отменить выбор и очистить всё избранное.

Основная операция — **toggle**, то есть переключение:

- Если элемент не выбран — выбрать.
- Если элемент выбран — отменить выбор.

### Где встречается такой подход

| Задача | Что хранить |
|---|---|
| Избранные статьи | Массив ID статей |
| Выбранные строки таблицы | Массив ID строк |
| Несколько выбранных фильтров | Массив значений фильтров |
| Выбор файлов для удаления | Массив ID файлов |
| Подписка на несколько тем | Массив ID тем |

Этот шаблон подходит, когда для каждого элемента достаточно ответа: **выбран или не выбран**.

Если нужно хранить количество, текст или другие изменяемые свойства элемента, потребуется другая структура состояния.

## 2. Универсальный порядок решения

### Шаг 1. Определить действия пользователя

Сначала перечисляю события, которые должен поддерживать интерфейс.

Для избранного:

1. Добавить статью.
2. Убрать статью.
3. Очистить избранное.

В другой задаче события могут быть такими:

- Ввести текст.
- Выбрать вкладку.
- Открыть окно.
- Увеличить количество.
- Изменить название задачи.

**Вопрос:** что пользователь может сделать?

### Шаг 2. Определить, какие данные меняются

В избранном меняется набор выбранных статей.

Сами статьи в этой задаче постоянны, поэтому список `articles` можно хранить вне компонента.

```jsx
const [favoriteIds, setFavoriteIds] = useState([]);
```

Пустой массив означает: изначально ничего не выбрано.

**Вопрос:** что компонент должен запомнить после действия пользователя?

### Шаг 3. Выбрать минимальное состояние

В состоянии храним данные, из которых можно получить всё необходимое для интерфейса.

Для избранного достаточно ID:

```jsx
const [favoriteIds, setFavoriteIds] = useState([]);
```

Количество и признак выбора вычисляем:

```jsx
const favoriteCount = favoriteIds.length;

const isFavorite = favoriteIds.includes(article.id);
```

Если нужен отдельный список избранных статей:

```jsx
const favoriteArticles = articles.filter((article) =>
  favoriteIds.includes(article.id)
);
```

Эти значения не требуют отдельных `useState`.

**Вопрос:** можно ли вычислить это значение из уже имеющихся данных?

### Шаг 4. Описать переход состояния

До написания обработчика записываю примеры:

| Было | Действие | Должно стать |
|---|---|---|
| `[]` | Нажать статью `2` | `[2]` |
| `[2]` | Нажать статью `4` | `[2, 4]` |
| `[2, 4]` | Нажать статью `2` | `[4]` |
| `[2, 4]` | Очистить | `[]` |

Теперь понятно, какую операцию выполнять.

**Вопрос:** каким должно стать состояние после конкретного события?

### Шаг 5. Выбрать способ обновления

Если следующее значение рассчитывается из предыдущего состояния, удобно использовать функцию обновления:

```jsx
setFavoriteIds((currentIds) => {
  // Возвращаем следующее состояние.
});
```

Если задаём готовое значение, передаём его напрямую:

```jsx
setFavoriteIds([]);
```

Например, введённый текст тоже можно передать напрямую:

```jsx
setQuery(event.target.value);
```

**Вопрос:** мне нужно предыдущее значение, чтобы получить следующее?

### Шаг 6. Связать состояние с интерфейсом

Определяю, какие части JSX зависят от состояния:

| Часть интерфейса | Выражение |
|---|---|
| Количество избранных | `favoriteIds.length` |
| Выбрана ли статья | `favoriteIds.includes(article.id)` |
| Заблокировать очистку | `favoriteIds.length === 0` |
| Подпись кнопки | Условие по `isFavorite` |

Обработчик меняет состояние. При следующем рендере компонент получает новое значение и описывает соответствующий интерфейс.

### Шаг 7. Проверить последовательность действий

Проверяю не только один клик, но и несколько связанных действий:

1. Выбрать первую статью.
2. Выбрать вторую.
3. Убрать первую.
4. Проверить, что вторая осталась.
5. Очистить избранное.

Так можно заметить случайную потерю других выбранных элементов.

## 3. Разбор переключения избранного

```jsx
function toggleFavorite(id) {
  // Следующее состояние зависит от предыдущего.
  setFavoriteIds((currentIds) => {
    // Проверяем, выбран ли этот ID.
    const alreadySelected = currentIds.includes(id);

    if (alreadySelected) {
      // Удаляем только нажатый ID.
      // filter возвращает новый массив.
      return currentIds.filter((currentId) => currentId !== id);
    }

    // Добавляем ID, сохраняя остальные.
    // Spread создаёт новый массив.
    return [...currentIds, id];
  });
}
```

### Как читать этот код

1. `id` — идентификатор статьи, на которую нажали.
2. `currentIds` — предыдущее состояние с учётом ранее поставленных в очередь обновлений.
3. `includes(id)` определяет, какую ветку выполнить.
4. `filter()` удаляет выбранный ID.
5. `[...currentIds, id]` добавляет новый ID.
6. `return` передаёт React следующее состояние.

`currentIds` — обычное имя параметра. Можно назвать его `prevIds`, но смысл останется тем же.

### Почему здесь нет дубликатов

Добавление выполняется только тогда, когда `includes(id)` вернул `false`.

### Почему нужен ID

ID позволяет определить статью независимо от её позиции в списке.

Если список отсортировать или отфильтровать, индекс может измениться. Стабильный ID продолжит обозначать ту же статью.

### Как связать обработчик с кнопкой

```jsx
<button
  type="button"
  aria-pressed={isFavorite}
  onClick={() => toggleFavorite(article.id)}
>
  {isFavorite ? "Убрать из избранного" : "В избранное"}
</button>
```

В `onClick` передаём функцию. Она вызовет обработчик при нажатии и передаст ID нужной статьи.

## 4. Как выбрать структуру состояния

| Что нужно помнить | Тип состояния | Начальное значение |
|---|---|---|
| Открыт ли блок | Boolean | `false` |
| Количество | Number | `0` |
| Текст поиска | String | `""` |
| Один выбранный элемент | ID или `null` | `null` |
| Несколько выбранных элементов | Массив ID | `[]` |
| Несколько связанных полей | Объект | `{ name: "", email: "" }` |
| Изменяемый список задач | Массив объектов | `[]` |
| Этап процесса | Строковый статус | `"idle"` |

### Один выбор и несколько выборов

Одна активная вкладка:

```jsx
const [activeTabId, setActiveTabId] = useState("articles");

function selectTab(id) {
  setActiveTabId(id);
}
```

Несколько выбранных статей:

```jsx
const [favoriteIds, setFavoriteIds] = useState([]);
```

Разница определяется условием задачи: **можно выбрать один элемент или несколько?**

## 5. Шаблоны обновления

> Фрагменты ниже — отдельные рецепты. Предполагается, что соответствующие состояния уже объявлены.

### Переключить Boolean

Подходит для раскрывающегося блока или меню.

```jsx
setIsOpen((current) => !current);
```

Если действие явно означает «закрыть», задаём конкретное значение:

```jsx
setIsOpen(false);
```

### Увеличить число

Подходит для счётчика или количества товара.

```jsx
setCount((current) => current + 1);
```

Уменьшить, не допуская отрицательного значения:

```jsx
setCount((current) => Math.max(0, current - 1));
```

### Записать текст из поля

```jsx
<input
  value={query}
  onChange={(event) => setQuery(event.target.value)}
/>
```

`value` связывает отображаемый текст с состоянием, а `onChange` обновляет его.

### Добавить элемент в массив

```jsx
setItems((currentItems) => [...currentItems, newItem]);
```

`newItem` должен быть подготовлен до обновления. Например, объект новой задачи со стабильным ID.

### Удалить элемент по ID

```jsx
setItems((currentItems) =>
  currentItems.filter((item) => item.id !== id)
);
```

### Изменить один объект в массиве

```jsx
setTasks((currentTasks) =>
  currentTasks.map((task) =>
    task.id === id
      ? { ...task, completed: !task.completed }
      : task
  )
);
```

Здесь:

- `map()` сохраняет количество элементов.
- У нужной задачи создаётся новый объект.
- Остальные задачи возвращаются без изменений.

### Изменить поле объекта

```jsx
setForm((currentForm) => ({
  ...currentForm,
  email: nextEmail,
}));
```

Spread сохраняет остальные поля.

### Быстрый выбор операции

| Что требуется | Что применить |
|---|---|
| Проверить наличие ID | `includes()` |
| Добавить элемент | Spread |
| Удалить элементы | `filter()` |
| Изменить нужный элемент | `map()` + копия объекта |
| Найти объект для отображения | `find()` |
| Получить количество | `.length` |
| Заменить состояние целиком | Setter с готовым значением |

## 6. Похожие задачи и их отличия

### Избранное → выбранные строки таблицы

Логика почти одинаковая:

```jsx
const [selectedIds, setSelectedIds] = useState([]);
```

Меняются названия и интерфейс. Проверка наличия, добавление и удаление остаются такими же.

### Избранное → аккордеон

Сначала уточняю правило открытия.

Если одновременно открыт только один блок:

```jsx
const [openId, setOpenId] = useState(null);

function toggleSection(id) {
  setOpenId((currentId) => currentId === id ? null : id);
}
```

Если можно открыть несколько блоков, подходит массив ID и шаблон избранного.

### Избранное → корзина

Массив ID подходит, только если нужно помнить наличие товара.

Если пользователь меняет количество, понадобится более богатая структура:

```jsx
const [cartItems, setCartItems] = useState([
  { productId: 1, quantity: 2 },
]);
```

Здесь повторное добавление может увеличивать количество, а не удалять товар.

Правило обновления берём из условия задачи.

### Избранное → список задач

Если меняются названия и статусы задач, храним сами изменяемые объекты:

```jsx
const [tasks, setTasks] = useState([
  { id: 1, title: "Изучить useState", completed: false },
]);
```

Для изменения одной задачи используем `map()`, для удаления — `filter()`.

### Избранное → поиск

В состоянии достаточно хранить запрос:

```jsx
const [query, setQuery] = useState("");

const normalizedQuery = query.trim().toLowerCase();

const visibleArticles = articles.filter((article) =>
  article.title.toLowerCase().includes(normalizedQuery)
);
```

Результат поиска вычисляется из списка и запроса.

### Задачи с запросами к серверу

`useState` может хранить данные, статус загрузки и ошибку, но сам не выполняет запросы.

Такие задачи дополнительно требуют определить:

- Когда запускать запрос.
- Что показывать во время ожидания.
- Что делать при ошибке.
- Как обрабатывать ответы, пришедшие в другом порядке.

Поэтому шаблон избранного не покрывает всю работу с сервером.

## 7. Частые ошибки

### Изменять массив состояния напрямую

Неправильно:

```jsx
favoriteIds.push(id);
setFavoriteIds(favoriteIds);
```

Для обновления создаём новый массив:

```jsx
setFavoriteIds((currentIds) => [...currentIds, id]);
```

Аналогично, копия массива не разрешает менять вложенные объекты напрямую. Изменяемый объект тоже нужно скопировать.

### Забыть return в функции обновления

Неправильно:

```jsx
setFavoriteIds((currentIds) => {
  currentIds.filter((currentId) => currentId !== id);
});
```

Правильно:

```jsx
setFavoriteIds((currentIds) => {
  return currentIds.filter((currentId) => currentId !== id);
});
```

### Вызвать обработчик при рендере

Неправильно:

```jsx
onClick={toggleFavorite(article.id)}
```

Правильно:

```jsx
onClick={() => toggleFavorite(article.id)}
```

### Ожидать новое состояние сразу после setter

```jsx
setCount((current) => current + 1);

console.log(count);
```

`count` в этом обработчике относится к текущему рендеру. Setter не заменяет эту локальную переменную: новое значение будет доступно при следующем рендере.

### Хранить вычисляемые данные отдельно

Количество избранных можно получить через:

```jsx
favoriteIds.length
```

Отдельное состояние для количества потребовало бы поддерживать два значения согласованными.

### Выполнять побочные действия внутри updater

Функция обновления должна вычислять и возвращать состояние.

Не помещаем в неё отправку запроса, уведомления или изменение внешних данных. В режиме разработки React может вызвать updater дважды для проверки его чистоты.

### Вызывать useState внутри условия или цикла

Хуки объявляем на верхнем уровне компонента или собственного хука, до условных ранних возвратов.

## 8. Проверка решения

Для избранного:

- [ ] Изначально ничего не выбрано.
- [ ] Первое нажатие добавляет статью.
- [ ] Повторное нажатие удаляет её.
- [ ] Выбор второй статьи сохраняет первую.
- [ ] Удаление одной статьи сохраняет остальные.
- [ ] Дубликаты ID не появляются.
- [ ] Счётчик соответствует числу выбранных статей.
- [ ] Очистка удаляет все выбранные ID.
- [ ] Подписи и `aria-pressed` соответствуют состоянию.
- [ ] Исходные массивы и объекты не изменяются напрямую.
- [ ] ID имеют согласованный тип: `2` и `"2"` — разные значения.

Важно: `useState` сохраняет данные между рендерами существующего компонента. Для восстановления избранного после перезагрузки страницы нужно отдельное хранение, например на сервере или в `localStorage`.

## 9. Как объяснять решение вслух

### Универсальная формулировка

> Пользователь может ___. Между рендерами нужно помнить ___, поэтому я храню ___ в состоянии. Начальное значение — ___. При событии ___ следующее состояние должно стать ___. Для обновления использую ___. Из состояния вычисляю ___. Проверю решение последовательностью ___.

### Пример для избранного

> Пользователь может выбирать несколько статей и отменять выбор. Статьи постоянны, поэтому в состоянии достаточно хранить массив выбранных ID. Изначально он пустой.
>
> При нажатии проверяю наличие ID. Если он уже выбран, удаляю его через filter. Если не выбран, добавляю через spread. Следующий массив зависит от предыдущего, поэтому использую функцию обновления.
>
> Количество и признак выбора вычисляю из массива ID. Проверяю повторное нажатие, выбор нескольких статей и очистку.

### Алгоритм, который можно переносить в другие задачи

1. Перечислить действия пользователя.
2. Определить изменяемые данные.
3. Выбрать минимальную структуру состояния.
4. Записать переходы: было → действие → стало.
5. Реализовать обновление без мутации.
6. Связать состояние с JSX.
7. Проверить последовательности действий и крайние случаи.

**Общий подход один. Конкретная структура данных и правила переходов зависят от задачи.**
