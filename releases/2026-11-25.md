# Practice release — November 25, 2026

This release contains exactly four independent exercises: two JavaScript tasks and two React tasks.

## 1. Conditions for all four exercises

### JavaScript 48 — Subscription renewal notices

**Main topic:** dates and internationalization  
**Supporting topics:** validation, array transformation, non-mutating sorting, DOM rendering  
**Difficulty:** confident junior+  
**Estimated time:** 45–60 minutes

**Scenario.** A subscription dashboard must show which services are overdue, renew today, or renew later. Product data may contain an invalid date or price.

**Input.** An array of { id, service, renewalDate, price }, an injected todayIso, a locale, and a currency.

**Expected behavior.**

- Accept only real YYYY-MM-DD calendar dates.
- Calculate whole calendar days from today.
- Classify every valid record as expired, today, or upcoming.
- Keep invalid records visible with a repair message.
- Sort valid records by daysUntil, placing invalid records last.
- Format the visible date and price with Intl.

**Ready when.**

- The input array remains unchanged.
- Results are deterministic because today is an argument.
- Dates do not shift because of the machine’s local time zone.
- Invalid data never produces NaN text or an uncaught error.

**Edge cases:** renewal today; impossible date such as 2026-02-31; zero price or invalid numeric price.

### JavaScript 49 — Podcast media controller

**Main topic:** this, regular functions, and bind  
**Supporting topics:** callbacks, object methods, copying references, remainder  
**Difficulty:** confident junior+  
**Estimated time:** 35–50 minutes

**Scenario.** A podcast page has Play/Pause and Next buttons. Its methods are registered as DOM event callbacks.

**Expected behavior.**

- The object stores its queue, current index, and playback state.
- Play/Pause toggles state and updates the interface.
- Next advances and wraps from the last episode to the first.
- Event callbacks retain the player as their receiver.
- The original playlist is protected from accidental reordering.

**Ready when.**

- Both buttons work repeatedly.
- An empty playlist does not throw.
- You can predict why detaching player.next loses the receiver.
- You can explain why an arrow method is not a universal fix.

**Edge cases:** empty playlist; one episode; repeated Next clicks.

### React 49 — Editable league standings

**Main topic:** derived state  
**Supporting topics:** controlled inputs, immutable nested updates, Map, multi-rule sorting  
**Difficulty:** junior+  
**Estimated time:** 50–70 minutes

**Scenario.** A community league administrator edits match scores and sees standings update immediately.

**Expected behavior.**

- Render controlled score inputs.
- A win gives three points; a draw gives one point to each team.
- Derive matches played, goal difference, and points.
- Sort by points, goal difference, then name.
- Update only the selected match immutably.

**Ready when.**

- Matches are the only source state.
- Standings are calculated during render.
- Keys are stable match ids and team names.
- Editing a score never mutates previous state.

**Edge cases:** 0–0 draw; away win; complete tie requiring alphabetical order.

### React 50 — Reservation waitlist promotion

**Main topic:** functional state updates and atomic transitions  
**Supporting topics:** immutable arrays, find, map, at, slice, derived counts  
**Difficulty:** junior+  
**Estimated time:** 45–60 minutes

**Scenario.** A workshop has numbered seats and a FIFO waitlist. Cancelling a reservation should immediately promote the first waiting guest.

**Expected behavior.**

- Cancelling an occupied seat removes its current guest.
- If someone is waiting, move the first waiting guest into that exact seat.
- Remove only that guest from the queue.
- If the queue is empty, mark the seat available.
- Derive occupied count from seats.

**Ready when.**

- Seats and queue update together in one transition.
- Previous arrays and objects are not mutated.
- Empty seats do not show Cancel.
- A status message describes the last transition.

**Edge cases:** empty waitlist; already empty seat; final occupied seat.

## 2. Interview-style hints and candidate answers

### Task 48 — How to reason

Ask whether dates are calendar days or timestamps, what input format is guaranteed, how invalid rows appear, and which locale and currency to use. Separate strict parsing, business transformation, and rendering. Normalize dates to UTC midnight and inject today.

**Candidate answer:** “I parse the exact ISO shape and verify the resulting date parts because JavaScript normalizes impossible dates. UTC midnight keeps the calendar-day calculation stable. I inject today so tests do not change tomorrow. Intl formats presentation, while numeric differences drive the rules.”

### Task 49 — How to reason

Ask who owns playback state, which receiver methods need, whether listeners will be removed, and what happens with an empty queue. Use regular methods, copy the playlist, bind each handler once, and use remainder for wraparound.

**Candidate answer:** “A regular function gets this from its call site. The event system invokes the supplied callback without player in front of it, so I bind once. An arrow method would capture lexical this, which is not the player object. A stored bound function can also be removed later.”

**Debug checkpoint:** predict detachedNext = player.next followed by detachedNext(). The call site no longer supplies player. In strict mode, this is undefined and property access throws.

### React 49 — How to reason

Ask for tie-break rules, numeric-input behavior, and whether team names are unique. Store only matches. Derive standings with a pure function and use Map keyed by team name.

**Candidate answer:** “Standings are completely determined by matches, so separate standings state could become stale. I use Map for one accumulator per team. The input handler uses a functional setter and copies only the matching object. Sorting runs after converting map values to an array.”

### React 50 — How to reason

Ask whether the queue is FIFO, whether promotion uses the cancelled seat, and what happens when nobody waits. Model the behavior as one pure transition and use one functional setter.

**Candidate answer:** “Cancellation and promotion are one transaction. I calculate the next seats and waitlist from the same current state value. I replace only the affected seat, use slice rather than shift, and derive the occupied count because storing it would add another synchronization problem.”

## 3. Step-by-step breakdowns

### Task 48

1. Match the exact ISO pattern.
2. Build a UTC date and compare its parts to reject normalized impossible dates.
3. Validate prices with Number.isFinite.
4. Calculate daysUntil from UTC-midnight values.
5. Choose status and message from the sign.
6. Return new objects and sort without mutating input.
7. Render with textContent.

**Common mistakes:** trusting any Date object, subtracting local dates across daylight-saving changes, sorting input in place.

**Manual checks:** today is zero; a date five days earlier is overdue by five; invalid data is last; changing locale affects text only.

**Alternative:** use [...result].sort(comparator) when toSorted support is uncertain.

### Task 49

1. Create regular object methods that read fields through this.
2. Copy the playlist.
3. Guard the empty queue.
4. Toggle state and render.
5. Advance with remainder.
6. Bind methods once before registration.

**Common mistakes:** passing the unbound method, using an arrow method and expecting dynamic this, or applying remainder with length zero.

**Manual checks:** toggle twice, wrap after the last episode, test one and zero episodes.

**Alternative:** a listener arrow that calls player.next() keeps the explicit receiver. A bound reference is easier to remove later.

### React 49

1. Keep match data in state.
2. Ensure a team accumulator exists.
3. Update played and goal difference for both teams.
4. Add points.
5. Convert values and apply all tie-breakers.
6. Update one match with map, spread, and a computed property.

**Common mistakes:** duplicate standings state, mutated match objects, sorting state, or unstable keys.

**Manual checks:** draw, home win, away win, zero, and a full tie.

**Alternative:** reduce into an object. Map communicates keyed records clearly and avoids prototype-key edge cases.

### React 50

1. Find and validate the seat.
2. Read the first waiting guest without mutation.
3. Replace only the cancelled seat.
4. Slice the queue only after promotion.
5. Return seats, queue, and message together.
6. Use a functional state setter.
7. Derive occupied count.

**Common mistakes:** shift on state, separate setters based on stale values, removing the wrong guest, or storing the count.

**Manual checks:** promote twice, empty the queue, then cancel with nobody waiting.

**Alternative:** separate state variables work for unrelated data, but one object is clearer for this atomic transition. A reducer is useful later when many booking actions exist.

### JavaScript 48 — script.js

```js
const subscriptions = [
  { id: 1, service: "Design Cloud", renewalDate: "2026-11-25", price: 19.99 },
  { id: 2, service: "Team Chat", renewalDate: "2026-11-28", price: 8 },
  { id: 3, service: "Archive Pro", renewalDate: "2026-11-20", price: 12.5 },
  { id: 4, service: "Broken record", renewalDate: "not-a-date", price: 10 },
];

// One calendar day in milliseconds. Named constants make date arithmetic readable.
const DAY_IN_MS = 24 * 60 * 60 * 1000;

// Converting an ISO date to UTC midnight avoids daylight-saving-hour surprises.
function parseIsoDateAtUtcMidnight(value) {
  const match = /^(\d{4})-(\d{2})-(\d{2})$/.exec(value);
  if (!match) return null;

  const [, year, month, day] = match.map(Number);
  const date = new Date(Date.UTC(year, month - 1, day));

  // Date normalizes impossible dates, so compare the parts to reject 2026-02-31.
  const isExactDate =
    date.getUTCFullYear() === year &&
    date.getUTCMonth() === month - 1 &&
    date.getUTCDate() === day;

  return isExactDate ? date : null;
}

function prepareRenewalNotices(items, todayIso, locale = "en-GB", currency = "EUR") {
  const today = parseIsoDateAtUtcMidnight(todayIso);
  if (!today) throw new Error("todayIso must be a valid YYYY-MM-DD date");

  const dateFormatter = new Intl.DateTimeFormat(locale, {
    day: "numeric",
    month: "short",
    year: "numeric",
    timeZone: "UTC",
  });
  const moneyFormatter = new Intl.NumberFormat(locale, {
    style: "currency",
    currency,
  });

  return items
    .map((item) => {
      const renewalDate = parseIsoDateAtUtcMidnight(item.renewalDate);
      const numericPrice = Number(item.price);

      // Invalid records remain visible so the interface can explain the problem.
      if (!renewalDate || !Number.isFinite(numericPrice) || numericPrice < 0) {
        return { ...item, status: "invalid", daysUntil: null, message: "Check subscription data" };
      }

      const daysUntil = Math.round((renewalDate - today) / DAY_IN_MS);
      const status = daysUntil < 0 ? "expired" : daysUntil === 0 ? "today" : "upcoming";
      const timing =
        daysUntil < 0
          ? `${Math.abs(daysUntil)} day(s) overdue`
          : daysUntil === 0
            ? "renews today"
            : `renews in ${daysUntil} day(s)`;

      return {
        ...item,
        status,
        daysUntil,
        message: `${dateFormatter.format(renewalDate)} · ${timing} · ${moneyFormatter.format(numericPrice)}`,
      };
    })
    // Copying before sort protects the mapped result if this comparator is reused elsewhere.
    .toSorted((a, b) => {
      if (a.status === "invalid") return 1;
      if (b.status === "invalid") return -1;
      return a.daysUntil - b.daysUntil;
    });
}

function renderRenewals(notices, container) {
  container.replaceChildren();
  notices.forEach((notice) => {
    const item = document.createElement("li");
    item.textContent = `${notice.service}: ${notice.message}`;
    item.dataset.status = notice.status;
    container.append(item);
  });
}

const notices = prepareRenewalNotices(subscriptions, "2026-11-25");
renderRenewals(notices, document.querySelector("#renewal-list"));

// Manual checkpoints: invalid last, overdue first, today's renewal next.
console.table(notices);
```

### JavaScript 49 — script.js

```js
const episodes = ["Execution Contexts", "Closures", "Maps and Sets"];

function createPlayer(playlist, output, toggleButton) {
  return {
    playlist: [...playlist], // Copy the array so outside code cannot reorder the player's queue accidentally.
    currentIndex: 0,
    isPlaying: false,

    render() {
      const currentTitle = this.playlist.at(this.currentIndex) ?? "No episodes";
      output.textContent = `${currentTitle} — ${this.isPlaying ? "playing" : "paused"}`;
      toggleButton.textContent = this.isPlaying ? "Pause" : "Play";
    },

    toggle() {
      if (this.playlist.length === 0) return;
      this.isPlaying = !this.isPlaying;
      this.render();
    },

    next() {
      if (this.playlist.length === 0) return;
      // Remainder wraps the index from the last episode back to zero.
      this.currentIndex = (this.currentIndex + 1) % this.playlist.length;
      this.render();
    },
  };
}

const output = document.querySelector("#now-playing");
const toggleButton = document.querySelector("#toggle");
const nextButton = document.querySelector("#next");
const player = createPlayer(episodes, output, toggleButton);

// A method passed directly becomes a plain callback, so its receiver would be the button.
// bind creates functions whose `this` permanently points to player.
const handleToggle = player.toggle.bind(player);
const handleNext = player.next.bind(player);

toggleButton.addEventListener("click", handleToggle);
nextButton.addEventListener("click", handleNext);
player.render();

// Debug checkpoint: `const broken = player.next; broken()` loses the player receiver.
// An arrow method would not fix this because arrows capture `this` from their outer scope.
```

### React 49 — App.jsx

```jsx
import { useState } from "react";

const initialMatches = [
  { id: 1, home: "Owls", away: "Foxes", homeScore: 1, awayScore: 1 },
  { id: 2, home: "Foxes", away: "Bears", homeScore: 2, awayScore: 0 },
  { id: 3, home: "Bears", away: "Owls", homeScore: 0, awayScore: 3 },
];

function buildStandings(matches) {
  const teams = new Map();

  const ensureTeam = (name) => {
    if (!teams.has(name)) teams.set(name, { name, played: 0, goalDifference: 0, points: 0 });
    return teams.get(name);
  };

  matches.forEach(({ home, away, homeScore, awayScore }) => {
    const homeTeam = ensureTeam(home);
    const awayTeam = ensureTeam(away);
    homeTeam.played += 1;
    awayTeam.played += 1;
    homeTeam.goalDifference += homeScore - awayScore;
    awayTeam.goalDifference += awayScore - homeScore;

    if (homeScore === awayScore) {
      homeTeam.points += 1;
      awayTeam.points += 1;
    } else if (homeScore > awayScore) {
      homeTeam.points += 3;
    } else {
      awayTeam.points += 3;
    }
  });

  // The table is derived from matches on every render; it is not duplicate state.
  return [...teams.values()].sort(
    (a, b) => b.points - a.points || b.goalDifference - a.goalDifference || a.name.localeCompare(b.name),
  );
}

export default function App() {
  const [matches, setMatches] = useState(initialMatches);
  const standings = buildStandings(matches);

  function updateScore(matchId, field, rawValue) {
    // Empty input becomes zero for this compact exercise; negatives are clamped to zero.
    const score = Math.max(0, Number(rawValue) || 0);
    setMatches((currentMatches) =>
      currentMatches.map((match) =>
        match.id === matchId ? { ...match, [field]: score } : match,
      ),
    );
  }

  return (
    <main>
      <h1>Community league</h1>
      <section aria-labelledby="scores-title">
        <h2 id="scores-title">Scores</h2>
        {matches.map((match) => (
          <p key={match.id}>
            {match.home} <input aria-label={`${match.home} score`} type="number" min="0" value={match.homeScore} onChange={(event) => updateScore(match.id, "homeScore", event.target.value)} />
            {" — "}
            <input aria-label={`${match.away} score`} type="number" min="0" value={match.awayScore} onChange={(event) => updateScore(match.id, "awayScore", event.target.value)} /> {match.away}
          </p>
        ))}
      </section>

      <h2>Standings</h2>
      <table><thead><tr><th>Team</th><th>Played</th><th>GD</th><th>Points</th></tr></thead><tbody>
        {standings.map((team) => <tr key={team.name}><td>{team.name}</td><td>{team.played}</td><td>{team.goalDifference}</td><td>{team.points}</td></tr>)}
      </tbody></table>
    </main>
  );
}
```

### React 50 — App.jsx

```jsx
import { useState } from "react";

const initialState = {
  seats: [
    { id: "A1", guest: "Maya" },
    { id: "A2", guest: "Leo" },
    { id: "A3", guest: null },
  ],
  waitlist: ["Nora", "Sam"],
  message: "",
};

function cancelReservation(currentState, seatId) {
  const seat = currentState.seats.find((item) => item.id === seatId);
  if (!seat?.guest) return currentState;

  const promotedGuest = currentState.waitlist.at(0) ?? null;
  const nextSeats = currentState.seats.map((item) =>
    item.id === seatId ? { ...item, guest: promotedGuest } : item,
  );

  return {
    seats: nextSeats,
    // Remove only the promoted first person; keep the queue unchanged when it is empty.
    waitlist: promotedGuest ? currentState.waitlist.slice(1) : currentState.waitlist,
    message: promotedGuest
      ? `${seat.guest} cancelled. ${promotedGuest} moved from the waitlist to ${seatId}.`
      : `${seat.guest} cancelled. ${seatId} is now available.`,
  };
}

export default function App() {
  const [booking, setBooking] = useState(initialState);

  function handleCancel(seatId) {
    // Functional state ensures the transition receives the latest queue and seats.
    setBooking((currentBooking) => cancelReservation(currentBooking, seatId));
  }

  const occupiedCount = booking.seats.filter((seat) => seat.guest).length;

  return (
    <main>
      <h1>Workshop reservations</h1>
      <p>{occupiedCount} of {booking.seats.length} seats occupied</p>
      <ul>
        {booking.seats.map((seat) => (
          <li key={seat.id}>
            <strong>{seat.id}</strong>: {seat.guest ?? "Available"}{" "}
            {seat.guest && <button type="button" onClick={() => handleCancel(seat.id)}>Cancel</button>}
          </li>
        ))}
      </ul>
      <h2>Waitlist</h2>
      {booking.waitlist.length > 0 ? <ol>{booking.waitlist.map((guest) => <li key={guest}>{guest}</li>)}</ol> : <p>The waitlist is empty.</p>}
      {booking.message && <p role="status">{booking.message}</p>}
    </main>
  );
}
```
