# JavaScript: сортировка по трём правилам
Выпуск: 6 ноября 2026.

## Условие
Каталог товаров нужно упорядочить: сначала в наличии, затем по возрастанию цены, затем по русскому названию.
Данные: 1 Блокнот false 200; 2 Папка true 500; 3 Альбом true 200; 4 Карандаш true 200; 5 Ластик false 100; 6 Альбом true 200.
Напиши sortProducts(items), возвращающую новый массив. При полном равенстве критериев сохраняется исходный относительный порядок.
Контракт: inStock — boolean, price — неотрицательное число, title — непустая русская строка; ID уникальны.
Готово: порядок ID 3,6,4,2,5,1; исходный массив и объекты не меняются.
Крайние случаи: товар не в наличии дешевле доступного; одинаковое наличие и цена; полное равенство критериев или пустой массив.
Время: 20–25 минут.

## Как рассуждать
1. Какое правило имеет наибольший приоритет?
2. Когда можно переходить к следующему сравнению?
3. Что должен вернуть comparator и где нужна копия?

Новый приём: localeCompare сравнивает строки с учётом языка; важен знак результата: отрицательный, 0 или положительный. Стабильная сортировка сохраняет исходный порядок, когда comparator возвращает 0.

## Примеры ответов вслух
«Сначала сравню наличие. Если оно различается, остальные признаки не должны влиять на решение. Дешёвый отсутствующий товар не поднимается выше доступного».
«Если разность равна нулю, перейду к цене, затем к названию. Number превращает флаги в 1/0. Для доступных первыми использую Number(b.inStock) - Number(a.inStock), для цены по возрастанию a.price - b.price».
«sort изменяет массив, поэтому сначала сделаю [...items]. Объекты только читаю. Для русских названий использую localeCompare с ru, не ожидая строго -1/1».
«Проверю дешёвый отсутствующий товар, одинаковую цену, равные названия и исходный порядок. Для полного равенства вернётся 0».

## Пошаговый разбор
1. Создай копию массива.
2. Сравни наличие.
3. Если оно одинаковое, сравни цену.
4. Если цена одинаковая, сравни название.
5. Верни результат сортировки.

Ошибки: сортировать входной массив; применять цену до наличия; comparator возвращает boolean; выполнять несколько sort без понимания приоритетов; ожидать ровно -1/1 от localeCompare.
Проверки: основной пример → 3,6,4,2,5,1; цена 100 у отсутствующего товара не поднимает его в доступную группу; 3 остаётся раньше 6; [] → [].
Альтернатива: сначала filter на доступные/отсутствующие, каждую группу сортировать по цене/названию, затем объединить. Приоритет наличия виден явно, но промежуточных массивов и кода больше. Удобно, когда группы ещё и отображаются отдельными секциями.

### script.js

```js
const products = [
  { id: 1, title: "Блокнот", inStock: false, price: 200 },
  { id: 2, title: "Папка", inStock: true, price: 500 },
  { id: 3, title: "Альбом", inStock: true, price: 200 },
  { id: 4, title: "Карандаш", inStock: true, price: 200 },
  { id: 5, title: "Ластик", inStock: false, price: 100 },
  { id: 6, title: "Альбом", inStock: true, price: 200 },
];

function sortProducts(items) {
  // sort изменяет массив: сортируем поверхностную копию.
  // Объекты только читаем, поэтому копировать их не требуется.
  return [...items].sort((a, b) => {
    // Правило 1: товары в наличии идут первыми.
    // true превращается в 1: b - a даёт приоритет a.inStock=true.
    const stockDifference = Number(b.inStock) - Number(a.inStock);
    if (stockDifference !== 0) return stockDifference;

    // Правило 2 действует только при одинаковом наличии.
    const priceDifference = a.price - b.price;
    if (priceDifference !== 0) return priceDifference;

    // Правило 3: алфавитный порядок русских названий.
    // Важен знак результата localeCompare, а не точное -1 или 1.
    return a.title.localeCompare(b.title, "ru");
  });
}

// Порядок ID: 3, 6, 4, 2, 5, 1.
// 3 и 6 равны по всем критериям: стабильная сортировка сохраняет их порядок.
console.log(sortProducts(products));
// Исходный порядок не меняется.
console.log(products);
console.log(sortProducts([])); // Пустой набор остаётся пустым.
```
