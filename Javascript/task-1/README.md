# Универсальный подход к решению задач с массивами JavaScript

> Сначала определить нужный результат, затем выбрать метод и только после этого писать код.

Этот алгоритм помогает решать задачи на поиск, фильтрацию, преобразование, сортировку и подсчёт данных.

## 1. Разобрать условие

Перед написанием кода ответить на три вопроса:

| Вопрос | Что уточнить |
|---|---|
| Что приходит на вход? | Массив чисел, строк или объектов? Какие поля есть у объектов? |
| Что нужно получить? | Массив, один элемент, индекс, число или `true / false`? |
| Какие есть ограничения? | Можно ли менять исходный массив? Что возвращать, если совпадений нет? |

### Пример условия

Получить названия опубликованных статей категории `JavaScript`.

**Разбор:**

- Вход — массив объектов с полями `title`, `category`, `published`.
- Выход — массив строк с названиями.
- Действия — отобрать подходящие статьи, затем получить названия.
- При отсутствии совпадений — вернуть пустой массив `[]`.
- Исходный массив и его объекты — сохранить.

**Как объяснить решение:**

> Здесь нужен массив названий. Сначала использую `filter` для отбора статей, затем `map` для преобразования объектов в строки.

## 2. Выбрать метод по нужному результату

| Задача | Метод | Вопрос к себе |
|---|---|---|
| Оставить все подходящие элементы | `filter` | Какие элементы оставить? |
| Преобразовать каждый элемент | `map` | Во что превратить каждый элемент? |
| Найти первый подходящий элемент | `find` | Какой один элемент нужен? |
| Найти индекс по условию | `findIndex` | Где находится подходящий элемент? |
| Найти индекс конкретного значения | `indexOf` | Где находится это значение? |
| Проверить наличие конкретного значения | `includes` | Есть ли это значение? |
| Проверить хотя бы одно совпадение | `some` | Есть ли хотя бы один подходящий элемент? |
| Проверить все элементы | `every` | Каждый элемент соответствует условию? |
| Получить общий итог | `reduce` | Что накапливать и с чего начать? |
| Упорядочить элементы | `toSorted` или `sort` на копии | По какому правилу сравнивать элементы? |
| Выполнить действие для каждого элемента | `forEach` | Какое действие выполнить? |

> Выбирать метод нужно по задаче и типу результата.

### Важные различия

- `filter` возвращает массив, даже если найден только один элемент.
- `find` возвращает элемент или `undefined`.
- `findIndex` и `indexOf` возвращают индекс или `-1`.
- `some`, `every` и `includes` возвращают `boolean`.
- `forEach` возвращает `undefined`.
- `sort` меняет исходный массив; `toSorted` создаёт новый.
- `map` и `filter` создают новый массив, но не копируют вложенные объекты.

## 3. Разбить задачу на простые действия

Сначала записать решение обычными словами:

1. Оставить опубликованные статьи.
2. Среди них оставить категорию `JavaScript`.
3. Получить названия оставшихся статей.

Затем сопоставить действия с методами:

```text
Отобрать элементы → filter
Преобразовать элементы → map
```

Два условия отбора можно объединить в один `filter`.

**Как объяснить решение:**

> У статьи должны одновременно выполняться два условия, поэтому объединю их через `&&`. Затем преобразую только оставшиеся статьи в названия.

## 4. Сформулировать логику для одного элемента

Метод организует обход массива, а callback описывает работу с одним элементом.

### Условие отбора

```js
// Статья должна быть опубликована
// и относиться к категории JavaScript.
article.published && article.category === "JavaScript"
```

### Преобразование

```js
// Из объекта статьи нужно получить строку с названием.
article.title
```

### Если задача требует reduce

Перед написанием callback определить:

1. Что будет аккумулятором: число, массив или объект?
2. Какое начальное значение нужно?
3. Как текущий элемент изменяет аккумулятор?
4. Что вернуть на следующий шаг?

Например, для суммы:

```js
// Начальный итог — 0.
// На каждом шаге прибавляем текущее число.
const total = numbers.reduce((sum, number) => sum + number, 0);
```

## 5. Предсказать результат на маленьком примере

До запуска кода проверить логику вручную.

| Статья | Опубликована | Категория | Оставляем |
|---|---|---|---|
| Основы JS | Да | JavaScript | Да |
| CSS Grid | Да | CSS | Нет |
| Методы массивов | Нет | JavaScript | Нет |

Ожидаемый результат:

```js
["Основы JS"]
```

**Как объяснить проверку:**

> Первый объект подходит под оба условия. Второй исключается по категории, третий — по публикации. После преобразования должен остаться один заголовок.

## 6. Написать решение

```js
// Исходные данные: массив объектов со статьями.
const articles = [
  {
    title: "Основы JS",
    category: "JavaScript",
    published: true,
  },
  {
    title: "CSS Grid",
    category: "CSS",
    published: true,
  },
  {
    title: "Методы массивов",
    category: "JavaScript",
    published: false,
  },
];

const titles = articles
  // Оставляем только опубликованные статьи категории JavaScript.
  // Оба условия должны выполняться одновременно.
  .filter(
    article =>
      article.published &&
      article.category === "JavaScript"
  )
  // Преобразуем каждый оставшийся объект в его название.
  .map(article => article.title);

// Результат — новый массив строк.
// Исходный массив и его объекты не изменены.
console.log(titles); // ["Основы JS"]
```

### Почему сначала filter, затем map

После `filter` остаются объекты со всеми нужными полями.

Если сначала получить только названия через `map`, поля `published` и `category` больше не будут доступны в элементах результата.

## 7. Проверить крайние случаи

- [ ] Пустой массив.
- [ ] Нет подходящих элементов.
- [ ] Один подходящий элемент.
- [ ] Все элементы подходят.
- [ ] Есть повторяющиеся значения.
- [ ] Совпадение находится на индексе `0`, если ищем позицию.
- [ ] Результат имеет нужный тип.
- [ ] Исходный массив сохранён, если это требуется.
- [ ] Callback возвращает значение там, где оно необходимо.

### Особенности, которые легко пропустить

```js
// findIndex возвращает 0 для первого элемента.
// Поэтому наличие совпадения проверяем через !== -1.
const index = articles.findIndex(
  article => article.category === "JavaScript"
);

if (index !== -1) {
  console.log("Статья найдена");
}
```

```js
// Если у стрелочной функции есть блок { },
// для преобразования нужен явный return.
const titles = articles.map(article => {
  return article.title;
});
```

```js
// Для пустого массива every возвращает true.
// Если список должен быть непустым, проверяем длину отдельно.
const allPublished =
  articles.length > 0 &&
  articles.every(article => article.published);
```

## Краткий алгоритм

1. Определить входные данные.
2. Назвать ожидаемый результат и его тип.
3. Разбить задачу на отдельные действия.
4. Выбрать метод для каждого действия.
5. Написать логику обработки одного элемента.
6. Предсказать результат на маленьком примере.
7. Написать код и проверить крайние случаи.
