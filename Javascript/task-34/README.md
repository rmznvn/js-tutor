# JavaScript: диапазон цен с необязательными границами
Выпуск: 9 ноября 2026.

## Условие
Каталог: ID1 «Бесплатный шаблон» 0 ₽; ID2 «Набор иконок» 500 ₽; ID3 «UI Kit» 1500 ₽; ID4 «Шаблон сайта» 3000 ₽.
Напиши filterByPrice(items, minInput, maxInput), где границы — строки из полей.
После trim пустая строка означает отсутствие границы, а "0" — реальное число 0. Обе границы включены.
Непустые строки преобразуются через Number. Результат обязан быть конечным неотрицательным числом. Если минимум больше максимума, верни ошибку.
Результат { items, error }: при ошибке items=[], error непустая; при корректном диапазоне error="", даже если товаров нет.
Контракт товаров: price — конечное неотрицательное число. Проверку исходных товаров не требуем. Формат числовой строки — понимаемый Number; десятичный разделитель — точка, не запятая.
Готово: входные данные не изменяются; без границ новый массив всех товаров; максимум "0" оставляет бесплатный товар; диапазон "500"–"1500" включает ID2/3.
Крайние случаи: пробельная граница и ноль; abc/Infinity/отрицательное число; обратный диапазон или корректная пустая выдача.
Время: 25–30 минут.

## Как рассуждать
1. Почему нельзя сразу выполнить Number над полем?
2. Чем ошибка ввода отличается от отсутствия результатов?
3. Где нужна проверка null вместо truthy/falsy?

Новый приём: Number.isFinite(value) проверяет, что значение является конечным числом. После Number он позволяет отвергнуть NaN и Infinity.

## Примеры ответов вслух
«Number пустой строки даст 0. Но пустая граница означает отсутствие ограничения, поэтому сначала trim и проверка пустоты. Отсутствие обозначу null, ноль сохраню числом».
«Разделю невалидный ввод и корректную выдачу без товаров через error. Пользователь должен понимать, исправлять поля или менять запрос».
«Проверю конечность и неотрицательность каждой заданной границы. Затем сравню минимум и максимум, если заданы оба».
«В filter объединю два ограничения через И. Проверки min === null и max === null отключат соответствующую границу, не потеряв 0. Проверю включённые границы и исходный массив».

## Пошаговый разбор
1. Очисти строки через trim.
2. Пустые преобразуй в null, остальные в числа.
3. Отвергни NaN, Infinity и отрицательные числа.
4. Проверь порядок границ.
5. Отфильтруй товары включительно по обеим границам.
6. Верни массив и сообщение ошибки отдельно.

Ошибки: Number("") теряет смысл отсутствия; if(max) игнорирует ноль; parseFloat("500abc") принимает некорректную строку частично; min/max сравниваются как строки; пустой результат ошибочно считается ошибкой.
Проверки: ""/"" → все; ""/"0" → ID1; " 500 "/"1500" → ID2/3; "1500"/"500" → ошибка; "abc"/"" → ошибка; "600"/"700" → [] без ошибки; []/""/"" → [] без ошибки.
Альтернатива: преобразовать и валидировать границы отдельно в форме, а функцию фильтрации принимать числа/null. Чистый фильтр короче и удобнее переиспользовать, но вызывающая сторона обязана соблюдать контракт. Здесь единая функция удобна для тренировки полного пути от строки поля к результату.

### script.js

```js
const products = [
  { id: 1, title: "Бесплатный шаблон", price: 0 },
  { id: 2, title: "Набор иконок", price: 500 },
  { id: 3, title: "UI Kit", price: 1500 },
  { id: 4, title: "Шаблон сайта", price: 3000 },
];

function filterByPrice(items, minInput, maxInput) {
  // Строки приходят из полей. Пустота означает отсутствие границы.
  // Проверяем её ДО Number, потому что Number("") равно 0.
  const minText = minInput.trim();
  const maxText = maxInput.trim();
  const min = minText === "" ? null : Number(minText);
  const max = maxText === "" ? null : Number(maxText);

  // Number.isFinite отвергает NaN и Infinity.
  // Допустимая граница — конечное неотрицательное число, включая 0.
  const invalidMin = min !== null && (!Number.isFinite(min) || min < 0);
  const invalidMax = max !== null && (!Number.isFinite(max) || max < 0);
  if (invalidMin || invalidMax) {
    return { items: [], error: "Введите неотрицательные конечные числа." };
  }

  if (min !== null && max !== null && min > max) {
    return { items: [], error: "Минимум не должен превышать максимум." };
  }

  return {
    // Обе границы включены. null отключает только свою проверку.
    // filter создаёт новый массив, сами товары не изменяет.
    items: items.filter((item) =>
      (min === null || item.price >= min) &&
      (max === null || item.price <= max)
    ),
    error: "",
  };
}

// Без границ возвращаются все товары.
console.log(filterByPrice(products, "", " "));
// Максимум 0 — реальное ограничение: только бесплатный товар.
console.log(filterByPrice(products, "", "0"));
// Включены обе границы: ID 2 и 3.
console.log(filterByPrice(products, " 500 ", "1500"));
// Ошибочный диапазон отличается от корректной пустой выдачи.
console.log(filterByPrice(products, "1500", "500"));
console.log(filterByPrice(products, "abc", ""));
console.log(filterByPrice(products, "600", "700"));
```
