# JavaScript: соседние статьи одной категории
Выпуск: 30 октября 2026.

## Условие
CMS задаёт порядок статей: a «Основы CMS» (webflow), b «Состояние» (react), c «Коллекции» (webflow), d «Динамические страницы» (webflow).
Создай чистую функцию getArticleNeighbors(items, currentId), возвращающую { previous, next }: объекты статей либо null.
Соседи должны принадлежать категории текущей статьи. Входной порядок сохраняется; переход с конца в начало запрещён. ID уникальны, строки; category заполнена.
Готово, если для c возвращаются a и d, исходный массив не меняется и функция не зависит от DOM.
Крайние случаи: первая/последняя статья; единственная в категории; неизвестный ID или пустой массив.
Время: 20–30 минут.

## Как рассуждать
1. Как понять категорию текущей статьи?
2. Где искать соседей: во всём массиве или внутри категории?
3. Нужно ли копировать объекты?

Начни с поиска текущей статьи. Определи контракт отсутствующего результата до обращения к её полям.

## Примеры ответов вслух
«Сначала использую find: мне нужен объект текущей статьи. Если он не найден, верну два null, потому что категория неизвестна».
«Через filter получу статьи той же категории в исходном порядке. Затем findIndex вернёт позицию текущей внутри этой группы. Соседи — элементы слева и справа».
«Я только читаю объекты, поэтому глубокая копия не нужна. filter создаёт новый массив. Возвращённые объекты остаются ссылками на исходные статьи; функция сама их не меняет. Проверю края, неизвестный ID и исходный порядок».

## Пошаговый разбор
1. Найди текущий объект через find.
2. При отсутствии верни два null.
3. Отфильтруй по его category.
4. Найди индекс текущей статьи в группе.
5. Возьми позиции index - 1 и index + 1.
6. Заменяй undefined на null через ??.

Ошибки: искать соседей в общем массиве; проверять индекс через if (!index), ведь 0 допустим; сортировать входной массив.
Проверки: c → a/d; a → null/c; d → c/null; b → null/null; missing и [] → null/null. Сравни массив до и после вызова.
Альтернатива: после нахождения текущей статьи пройти циклом влево и вправо до первого совпадения категории. Не создаёт промежуточный массив, но требует двух циклов и больше проверок. Удобно, если нужны только два соседа очень большого списка.

## Запуск
Открой index.html и консоль браузера. Это упражнение на данные: настоящие ссылки CMS пока не создаём.

### script.js

```js
const articles = [
  { id: "a", title: "Основы CMS", category: "webflow" },
  { id: "b", title: "Состояние", category: "react" },
  { id: "c", title: "Коллекции", category: "webflow" },
  { id: "d", title: "Динамические страницы", category: "webflow" },
];

// Контракт: уникальные строковые ID; массив уже расположен
// в нужном редактору порядке. Функция ничего не сортирует.
function getArticleNeighbors(items, currentId) {
  const current = items.find((item) => item.id === currentId);

  // Если текущей статьи нет, определять её категорию невозможно.
  if (!current) return { previous: null, next: null };

  // filter сохраняет относительный порядок и не меняет items.
  const related = items.filter(
    (item) => item.category === current.category
  );
  const index = related.findIndex((item) => item.id === currentId);

  return {
    // За границами массива получается undefined.
    // Возвращаем согласованный контракт: статья либо null.
    previous: related[index - 1] ?? null,
    next: related[index + 1] ?? null,
  };
}

// Для c соседи a и d: статья b относится к другой категории.
console.log(getArticleNeighbors(articles, "c"));
// У первой статьи нет предыдущей; у единственной b нет обоих соседей.
console.log(getArticleNeighbors(articles, "a"));
console.log(getArticleNeighbors(articles, "b"));
// Неизвестный ID и пустой массив дают два null без ошибки.
console.log(getArticleNeighbors(articles, "missing"));
console.log(getArticleNeighbors([], "a"));
```
