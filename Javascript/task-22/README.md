# Перестановка пунктов меню — JavaScript

Выпуск **2026-10-26**. Время: 25–35 минут.

## Условие

В редакторе навигации пункт можно поднять или опустить на одну позицию. Реализуй чистую функцию moveMenuItem(items, id, direction).

### Входные данные и критерии готовности

- Данные: home — Главная, media — Медиацентр, contacts — Контакты. ID уникальны.
- direction=-1 означает вверх, direction=1 — вниз.
- При допустимом перемещении вернуть новый массив; сами объекты не изменять.
- Неизвестный ID, другое направление и выход за границы возвращают исходный массив без изменений.
- Порядок остальных пунктов сохраняется.

### Крайние случаи

- Поднять первый или опустить последний.
- Несуществующий ID или пустой массив.
- Два последовательных перемещения одного пункта.

## Как рассуждать

- Зачем ID, если нужно работать с индексами?
- Почему достаточно поверхностной копии?
- Когда проверять границы?

Перед кодом определи вход, результат одного действия и ограничения. Отдели хранимые значения от производных; предскажи поведение на маленьком примере.

## Примеры ответов вслух

> «ID обозначает сам пункт независимо от его позиции. findIndex найдёт актуальную позицию для обмена.»

> «Меняется порядок ссылок в массиве, поля объектов не редактируются. Создам [...items] и поменяю местами два элемента; глубокая копия не нужна.»

> «До создания результата проверю индекс и соседнюю позицию. Недопустимая операция вернёт прежний массив. Проверю первый, последний, неизвестный ID и пустой список.»

## Пошаговый разбор

1. Проверить направление -1/1.
2. Найти индекс по ID.
3. Вычислить соседний индекс и проверить границы.
4. Создать поверхностную копию массива.
5. Поменять местами соседние элементы деструктуризацией.
6. Вернуть новый массив.

## Типичные ошибки

- Менять местами элементы прямо в items — мутация входа.
- index=-1 не означает последний найденный пункт: это отсутствие результата.
- Нельзя использовать устаревший индекс как ID.

## Альтернативный способ

Скопировать массив, извлечь элемент через splice и вставить на соседнюю позицию. На копии splice допустим; он удобнее для перемещения на произвольный индекс, но обмен короче для шага ±1.

## Ручная проверка

media вверх → media,home,contacts; media вниз → home,contacts,media. Границы, неизвестный ID и пустой список не меняются. Убедись, что исходный порядок и ссылки на объекты сохранены.

## Запуск

Открой index.html. Чистая функция выводит примеры в DevTools → Console.

### script.js

```js
const menuItems = [
  { id: "home", title: "Главная" },
  { id: "media", title: "Медиацентр" },
  { id: "contacts", title: "Контакты" },
];

function moveMenuItem(items, id, direction) {
  // Контракт направления: только -1 (вверх) или 1 (вниз).
  if (direction !== -1 && direction !== 1) return items;

  const index = items.findIndex((item) => item.id === id);
  if (index === -1) return items; // Неизвестный ID ничего не меняет.

  const nextIndex = index + direction;
  if (nextIndex < 0 || nextIndex >= items.length) return items;

  // Порядок меняем в новом массиве. Сами объекты не редактируем,
  // поэтому поверхностной копии достаточно.
  const result = [...items];
  [result[index], result[nextIndex]] = [result[nextIndex], result[index]];
  return result;
}

// Медиацентр поднимается перед Главной; исходный menuItems не меняется.
console.log(moveMenuItem(menuItems, "media", -1));
// Попытка поднять первый пункт — безопасное отсутствие изменений.
console.log(moveMenuItem(menuItems, "home", -1));

```
